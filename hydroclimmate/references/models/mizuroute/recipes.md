# mizuRoute — bounded recipes

Each recipe: inputs → minimal check → steps → cost → what invalidates the shortcut. **Cost is in files and records, not seconds: no mizuRoute run exists here.** Conventions and traps first: [card.md](card.md), [failures.md](failures.md). Source root `28514dea` (v3.1.1); a bare `file:line` means `route/build/src/file.f90`, **sa** = its `standalone/`.

## 1. Handing a land model's runoff to mizuRoute

**Inputs**: the land model's runoff field, its HRU or grid ids, its time axis, its units. **Minimal check**: mizuRoute needs a **rate**, not a depth per step or a volume — decide that first. **Steps**: (1) sum the land model's surface and subsurface components yourself — mizuRoute reads one variable, named by `<vname_qsim>`. (2) Convert to a rate spellable in `<units_qsim>` as `m|mm` over `d|h|s`; VIC's `OUT_RUNOFF`/`OUT_BASEFLOW` and HRLDAS's `SFCRNOFF`/`UGDRNOFF` are **not** rates, so divide by the interval first. (3) Give the file a `time` variable with `units` and `calendar` attributes, or supply `<ro_time_units>`/`<ro_calendar>`; the simulation's calendar is then taken from the runoff file. (4) Make the spacing uniform: it is measured from the axis and must be constant to `maxTimeDiff` ~ 1.16e-5 s (`public_var:28`), and it, not `<dt_ro>`, becomes the input step. (5) Shape the variable `(time, hru)` with an id variable, or `(time, lat, lon)` for the grid. **Cost**: one header read for units, calendar, spacing and rank. **Invalidated by**: a producer that already applied a hillslope delay — use `<doesBasinRoute> 0`; a `_FillValue` absent with no `<input_fillvalue>` given, which logs a warning and uses `-9999`; ocean written as `0`, which the remapper averages in ([failures.md](failures.md)).

## 2. Validating a network topology file before a run

**Inputs**: the topology NetCDF and the control file's `<varname_*>` keys. **Minimal check**: resolve every name you rely on with `tools/hcm_lookup.py --pack mizuroute <NAME>`; a channel-geometry name mizuRoute does not find is **not** an error. **Steps**: (1) confirm the two dimensions named by `<dname_sseg>` and `<dname_nhru>` exist. (2) Confirm `segId`, `downSegId`, `HRUid`, `hruSegId`, `area`, `length`, `slope` (under their configured names) are present — these are the required set. (3) Check that every `hruSegId` occurs in `segId`, and that `downSegId` is closed: each value is a `segId` or a terminal marker. (4) Decide geometry explicitly: under `<hydGeometryOption> 0` only the variables that exist are read, so list them and accept that the rest will be `wscale*sqrt(totalArea)`, `dscale*sqrt(totalArea)`, the namelist `mann_n`, side slope 0; and that under `<floodplain> F`, the default, every reach's `depth` is overwritten with `high_depth` after the read (`process_ntopo:189-194`), so a file depth acts only under `<floodplain> T`. (5) With lakes, confirm `islake` and `lakeModelType`, and, under `<is_vol_wm> T`, that no lake carries both a `LakeTargVol` flag and a type 0-3 — the conflict is checked only then (`read_streamSeg:392-400`). **Cost**: one header plus two id-set comparisons. **Invalidated by**: relying on `<ntopAugmentMode>` to fix the file — it writes a new network and **ends the run**; a reach whose `length <= 0`, silently reset to 100 m (`process_ntopo:297-300`).

## 3. Choosing and configuring a routing method

**Inputs**: `<route_opt>`, `<dt_qsim>`, the parameter namelist, the channel geometry you have. **Minimal check**: what does the network carry? IRF needs only `length` and `slope` plus `velo`/`diff`; KW, MC and DW need width, depth, Manning's n and side slope, and invent any that is missing. **Steps**: (1) pick digits — `1` IRF, `2` KWT, `3` KW, `4` MC, `5` DW, `0` accumulation — and concatenate them to run several at once; each writes its own variables; an invalid digit aborts with "expect digits 1-5" although `0` is accepted (`read_control:588,594-595`). (2) Set `<dt_qsim>` to at most 86400 s and an exact divisor of it. (3) Provide all three namelist groups: `&HSLOPE`, `&IRF_UH`, `&KWT` are read unconditionally. (4) Decide `<hw_drain_point>` and `<min_length_route>` knowingly — they change headwater and short-reach behaviour for IRF, KW, MC and DW, and nothing for KWT. **Cost**: no data read; a configuration decision. **Invalidated by**: expecting KW or DW to sub-cycle at a long step — only MC does ([processes.md](processes.md)); expecting `<floodplain>` to act under IRF or KWT, where no flood volume is computed; using `<tracer>` without digit 5, which aborts.

## 4. Closing the balance between input runoff and outlet discharge

**Inputs**: `basRunoff` (or input runoff and HRU areas), the outlet discharge, the per-method `*volume`, the period. **Minimal check**: let the model do it — `<checkMassBalance> T` prints the seven domain terms and the residual, per active method per step. **Steps** by hand: inflow is `sum_h(area_h * basRunoff_h) * dt` over the period; outflow `Q_outlet * dt`; storage change the outlet-method `*volume` differenced between last and first records **over every reach**, not just the outlet. Residual = inflow − outflow − ΔS. **Cost**: two records of `*volume` over all reaches, one pass over `basRunoff` and the outlet. **Invalidated by**: treating a per-method `*volume` as a window mean — it is the window's last value, while `*floodVolume` is a mean; a domain with more than one outlet (criterion `DREACHI == -1 .and. DREACHK <= 0`); lakes on, where the residual legitimately carries the `<LakeInputOption>` inconsistency ([failures.md](failures.md)); water management on, where abstraction is a real term.

## 5. Comparing two routing schemes

**Inputs**: one run with two digits in `<route_opt>`. **Minimal check**: run them **together**, not as two runs — both then see identical lateral inflow, network and time stepping, so the only difference is the channel solution. **Steps**: (1) set `<route_opt>` to both digits and, if either is KW, MC or DW, turn on their `*volume` too. (2) Compare `XXroutedRunoff` reach by reach on the common `reachID`. (3) Attribute: a timing difference is the scheme; a difference in the outlet period total is storage still in transit plus, for MC, its sub-stepping. (4) Keep `<hw_drain_point>` and `<min_length_route>` fixed, since they reach the two schemes identically only when both are in {IRF, KW, MC, DW}. **Cost**: one run, two variables. **Invalidated by**: comparing against KWT while changing those two keys, which KWT ignores; comparing `sumUpstreamRunoff` with a routed series, which has no transport at all; a generic-naming run, where the two collapse to one name ([failures.md](failures.md)).

## 6. Daily or monthly totals from an outlet series

**Inputs**: the discharge variable, `time`, `time_bounds`, `<dt_qsim>` and `<outputFrequency>`. **Minimal check**: read `time_bounds[k]` for one record and confirm what `time[k]` is — the window **start** unless `<histTimeStamp_offset>` was set, or the midpoint in coupled mode. **Steps**: each record is the time mean of the discharge over its window, so a period volume is `sum_k Q_k * (t_bnd[k,1] - t_bnd[k,0])`, and a period mean flow is that volume over the period. Bin left-closed: a record stamped `2000-01-01` under daily output covers 1 January. **Cost**: one pass over the variable plus `time_bounds`. **Invalidated by**: summing `Q` and multiplying by a nominal interval when `<outputFrequency>` is monthly and windows differ in length; mixing in a per-method `*volume`, which is the window's last value, not a mean; a file boundary, since `<newFileFrequency>` may split a period across files.

## 7. Restart continuity check

**Inputs**: the restart file, both control files, the history records either side of the boundary. **Minimal check**: the task count must match; nothing else is compared — not the network, not `<route_opt>`, not the parameters. **Steps**: (1) read `restart_time`/`time_bound` from the state file and confirm the continuing run's `<sim_start>` is that instant; remember the file name is stamped with the **next** step, and that under `<restart_write> specified` or a periodic value the drop-off is the requested date minus one `<dt_qsim>`, while `last` does not subtract. (2) Diff the two control files and confirm `<route_opt>`, `<doesBasinRoute>`, `<dt_qsim>`, `<is_lake_sim>`, `<floodplain>` and the parameter namelist are identical. (3) Compare a reach's `*volume` either side of the boundary: with `<outputFrequency> 1` it should continue smoothly. (4) Confirm the same MPI task count. **Cost**: two records, three text files. **Invalidated by**: a partial output window at the boundary — buffers are restored from the restart file, so the first new record may average across it; a `<continue_run> T` run, which appends to the history file named in `rpointer.rof`.

## 8. Building the topology and remap files

**Inputs**: reach and HRU polygons; for remapping, the source grid or HRU set. **Minimal check**: build to recipe 2's list, then run it. **Steps**: (1) write the seven required variables on `<dname_sseg>`/`<dname_nhru>`, marking every terminal reach with a `downSegId` that is no reach's `segId`; many HRUs may share one `segId`. (2) Derive the computed fields once with `<ntopAugmentMode> T`, which writes `<fname_ntopNew>` and ends the run. (3) For the remap file, give each network HRU its `num_qhru` and take weights and source ids in that same order; the 1-D path re-checks every stored id against the runoff file's id array (`process_remap:85-104,217-229`). **Cost**: one augmentation run. **Invalidated by**: reordering the runoff HRU axis afterwards.

## 9. When a full re-run is NOT needed

- No data read: which variables a configuration will write ([processes.md](processes.md)); whether a control file parses; whether the pack applies to a checkout ([version.md](version.md)).
- One header: units, calendar and spacing of the runoff input; reach and HRU counts; whether channel geometry is in the topology file.
- Two records: a storage change from `*volume`; whether two routing methods differ at a reach.
- A full pass **is** needed for a period volume, an extreme, a hydrograph comparison and the closures above.
