## One actual offline A/B probe

[Structured evidence](v0.6-offline-probe.json) retains the identical prompt, completed
command traces, answers, provider usage and hashes of the read fixture files. A had the
v0.6 workflow with knowledge hooks and model packs removed; B also had the packs. Each
used a fresh ephemeral Codex CLI session, default model selection and a 180-second limit.
The CLI did not emit its resolved model identifier in the captured JSONL; the comparison
used the same settings but is not a reproducible fixed-model benchmark.

Web search was disabled and model-generated shell commands ran in a read-only sandbox.
Only local `sed`/`rg` commands were observed, with no external retrieval. This is an
observed offline-knowledge probe, not a packet-level network-isolation audit. The model
service itself required connectivity. Explicit workflow invocation means triggering was
not measured. Raw transient logs remained outside the repository; the compact evidence
retains command lists and final answers without copying all read documentation.

| Measure | A: workflow only | B: with knowledge |
|---|---|---|
| Completion | Exit 0, 34.6 seconds | Exit 0, 40.0 seconds |
| Primary feature | Understand | Understand |
| Supplemental content | Analyze plus local file/search listing | Model index; ISSM outputs, overview and sources |
| Unique fully read files | 4 | 7 |
| Fully read file words | 2,048 | 2,802 |
| Observed command-output words | 2,209 | 2,802 |

| Linear-triangle mean and limits | Correct: 2.5, stated conditions | Correct: 2.5, stated conditions |
| Unrelated model files loaded | None | None |

Assessment: both answers were correct on this single composite question. B supplied
traceable local model evidence; A relied on prior knowledge and workflow-level checks.
B read more text, so this probe provides **no evidence of context savings or improved
accuracy**. Provider usage includes repeated system/context tokens and cache effects;
it is not interchangeable with the size of the knowledge loaded or a monetary cost.
Reading Analyze in A was a justified dependency, not a routing failure.

## Environment issues and remaining coverage

The first CLI readiness attempt failed because the outer sandbox blocked state initialization.
A user-approved retry initialized successfully; a separate READY-only check completed before
A/B scoring. No failed startup was counted as a scientific failure or a negative-trigger pass.

The 24 trigger cases and 12 knowledge cases are fixtures, not all measured outcomes.
No spontaneous trigger rate, multi-run reliability, other-model answer accuracy, full
unsupported-API behavior test, real simulation or installation compatibility was measured.
The synthetic arithmetic checks validate only the stated calculations, not ISSM physics.
No models/skills were installed and no scientific jobs were submitted. Further tests should
use the same protocol and report evidence without recasting these observations as a pass rate.
