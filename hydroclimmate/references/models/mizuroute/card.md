# mizuRoute — card

Pinned to mizuRoute `28514dea` (tag `v3.1.1`) ([version.md](version.md)); `path:line` is relative to that root. Any name: `tools/hcm_lookup.py --pack mizuroute <NAME>`, from `catalogs/*.yaml` — **not exhaustive**; read each `note`. Shorthand: **src** = `route/build/src`, **sa** = `src/standalone`.

**What it is and is not.** A river-network router: it takes a runoff **rate per HRU** and moves it down a reach network, computing no land physics — no infiltration, no evaporation except over lake surfaces. From upstream it needs one variable whose units string `<units_qsim>` is `<length>/<time>`, length `m|mm`, time `d|day`, `h|hr|hour`, `s|sec|second`, anything else fatal (`src/read_control.f90:443-474`), on an HRU or grid axis with an id and a time axis, plus a mapping to network HRUs.

**Two builds.** Standalone is `sa/route_runoff.f90`; its one argument is the control file (`:50-51`). The coupled build sets `runMode = 'cesm-coupling'`, which changes file names, moves the history stamp to the window midpoint and adds four host-side runoff/area keys (`src/public_var.f90:206-210`). Everything here is standalone unless it says otherwise.

**Files.** *Control*: ASCII, one `<key>  value  ! comment` per line — the `!` is **required**, a line without one fatal — a TAB in a value fatal, and **an unrecognised `<key>` fatal, not ignored** (`src/read_control.f90:100-118,374-378`). *Network topology*: one NetCDF, dimensions `<dname_sseg>`/`<dname_nhru>`. *Runoff*: `<fname_qsim>` is a NetCDF, a text file listing NetCDFs, or a shell wildcard — tested in that order (`ls` for the wildcard) (`sa/model_setup.f90:242-256`). *Remap*: NetCDF, read only when `<is_remap> T`. *Parameters*: a namelist with exactly three groups, `&HSLOPE`, `&IRF_UH` and `&KWT`, all read unconditionally (`src/read_param.f90:26-38`). *History*: `<output_dir><case_name>.h.<stamp>.nc`, `<stamp>` being `YYYY`, `YYYY-MM` or `YYYY-MM-DD-SSSSS` by `<newFileFrequency>`, from the step that **opened** the file — `daily` stamps the next day if `hfile_dayStamp` is `period-end`, no control key setting it (`src/write_simoutput_pio.f90:355-386`, `src/globalData.f90:132`). *Restart*: `<restart_dir><case_name>.r.YYYY-MM-DD-SSSSS.nc`, stamped with the **next** step, not the one finished (`src/write_restart_pio.f90:185,231,241-249`), plus `rpointer.rof`.

**Routing methods.** `<route_opt>` is a *digit string*: `0` accumulation, `1` IRF, `2` KWT, `3` KW, `4` MC, `5` DW; `35` runs KW and DW together and writes both (`src/read_control.f90:583-597`, `src/public_var.f90:74-80`). Each active method has its own discharge, volume, state and history variables.

**Time and units.** `<dt_qsim>` must be `<= 86400` s and divide it exactly; a numeric `<outputFrequency>` must satisfy `mod(86400, n*dt) == 0` (`src/read_control.f90:547-563`). The runoff step `<dt_ro>` is **overwritten** by the spacing of the input time axis, which must be uniform across all files to `maxTimeDiff` = `1/secprday` ~ 1.16e-5 s — the differences are in seconds, so this is effectively exact (`src/public_var.f90:28`, `sa/model_setup.f90:482,492-502`). Runoff for a step is the fraction-weighted **mean** of the records it spans, not a sum (`sa/read_runoff.f90:311-325`).

**What a record means.** Every history value is the **mean over the output window** — except the five per-method `*volume` variables and `soluteMass`, which carry the window's **last** value; `*floodVolume` and `*height`, despite the names, are means (`src/histVars_data.f90:229-243,259-305`). The `time` coordinate is the window's **start** plus `<histTimeStamp_offset>` (default 0); `time_bounds` carries both ends (`src/historyFile.f90:364-373`).

**Restart.** The state file stores the task count; restarting onto a **different number of MPI tasks is fatal** (`src/read_restart.f90:87-96`). It carries a time bound; the continuing run starts one `<dt_qsim>` after it (`src/init_model_data.f90:604-608`).
