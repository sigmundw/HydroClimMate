# VIC — bounded recipes

Each recipe: inputs → minimal check → steps → cost → what invalidates the shortcut. **Cost is in files and records read, not seconds: no VIC run exists.** Conventions and traps first: [card.md](card.md), [failures.md](failures.md). Source root VIC `14a371a8`; **cl** = `vic/drivers/classic/src`, **sh** = `vic/drivers/shared_all/src`, **shim** = `vic/drivers/shared_image/src`.

## 1. Period total or mean

**Inputs**: the variable's aggregation type and the records of the period. **Minimal check**: resolve the type with `tools/hcm_lookup.py --pack vic <NAME>`, or from its `cell_methods` attribute in image output. **Steps**: a `SUM` variable already holds the window total, so the period total is the sum of the records. An `AVG` variable holds the window mean, so the record mean is the period mean **only when every window has the same length** — under monthly aggregation, weight by window length. An `END` or `BEG` variable is one instant: sample or difference it, never sum it. **Cost**: one pass for `SUM` and `AVG`; two records to difference an `END` state. **Invalidated by**: a fifth `OUTVAR` field overriding the default type; monthly or yearly aggregation with an unweighted mean; a partial first or last window.

## 2. Water balance closure

**Inputs**: the fluxes `OUT_PREC`, `OUT_EVAP`, `OUT_RUNOFF`, `OUT_BASEFLOW` and, with lakes, `OUT_LAKE_CHAN_IN` (`SUM`, mm); the states `OUT_SOIL_LIQ`, `OUT_SOIL_ICE`, `OUT_SWE`, `OUT_SNOW_CANOPY`, `OUT_WDEW`, `OUT_SURFSTOR` (`END`). **Minimal check**: VIC computes the residual itself — request `OUT_WATER_ERROR`. **Steps**: the code's identity, term for term (`sh/put_data.c:515-530,1062`), is `error = inflow - outflow - (storage - last_storage)`, with `inflow = OUT_PREC + OUT_LAKE_CHAN_IN`, `outflow = OUT_EVAP + OUT_RUNOFF + OUT_BASEFLOW` and `storage = sum_layers(OUT_SOIL_LIQ + OUT_SOIL_ICE) + OUT_SWE + OUT_SNOW_CANOPY + OUT_WDEW + OUT_SURFSTOR`. Sum the fluxes over the period and difference the states between the first and last records. **Cost**: one pass for the fluxes plus two records for the states, or two if you trust `OUT_WATER_ERROR`. **Invalidated by**: the residual being formed **per model step before aggregation** and defaulting to `AVG`, so the aggregated value is a mean per-step residual — multiply by the steps per window before comparing with a summed flux; a period starting at the run's first record; lakes on, where `OUT_SURFSTOR` needs a correct `RESOLUTION`.

## 3. Energy balance closure

**Inputs**: `OUT_SWNET`, `OUT_LWNET`, `OUT_LATENT`, `OUT_LATENT_SUB`, `OUT_SENSIBLE`, **`OUT_ADV_SENS`**, `OUT_GRND_FLUX`, `OUT_DELTAH`, `OUT_FUSION`, `OUT_ADVECTION`, `OUT_DELTACC`, `OUT_SNOW_FLUX`, `OUT_RFRZ_ENERGY` — all W/m2, all `AVG`. **Minimal check**: `FULL_ENERGY` must be true, or `OUT_ENERGY_ERROR` is -99999 and there is no closure. **Steps**: the code's identity (`sh/put_data.c:538-552,1079`) is `error = (OUT_SWNET + OUT_LWNET) - (OUT_LATENT + OUT_LATENT_SUB) - (OUT_SENSIBLE + OUT_ADV_SENS) - (OUT_GRND_FLUX + OUT_DELTAH + OUT_FUSION) + (OUT_ADVECTION - OUT_DELTACC + OUT_SNOW_FLUX + OUT_RFRZ_ENERGY)`. Signs: net radiation positive, the latent, sensible and ground groups subtracted, the snow group **added** with `OUT_DELTACC` alone **negative** inside it. Omitting `OUT_ADV_SENS`, or adding `OUT_DELTACC`, gives a residual that is not the model's. **Cost**: one record per term, per window. **Invalidated by**: `FULL_ENERGY FALSE`, where the surface temperature is the air temperature and the fluxes are written but do not close; averaging -99999, which yields -99999; treating the aggregated `OUT_ENERGY_ERROR` as a period total — like the water error, it is a per-step residual averaged over the window.

## 4. Comparing two runs differing in one option

**Inputs**: two global parameter files, identical forcing, parameters and dates. **Minimal check**: diff them, confirm exactly one line differs and that it is not one of the order-dependent or silently-ignored ones ([failures.md](failures.md)). **Steps**: confirm both runs wrote the same records on the same time axis; identify from [processes.md](processes.md) which variables the option can reach and compare only those; difference the last record first. Where an option changes the variable **set** (lakes, carbon, frozen soil, routing), compare the intersection. **Cost**: two records per variable to decide whether anything changed; a full pass only if it did. **Invalidated by**: a second difference the option itself introduces — `FROZEN_SOIL TRUE` forces `QUICK_FLUX FALSE`, changing the solver and node grid; a different `RESOLUTION`, which changes the lake simulation; a different `BASEFLOW`, which reinterprets four soil columns.

## 5. Validating inputs before a run

**Inputs**: the global parameter file, the parameter tables or NetCDF, one forcing file. **Minimal check**: reproduce the reader's arithmetic on one cell. **Steps, classic**: count the whitespace-separated columns of one soil line against the reader's gated order — from the catalogs, not from `docs/Documentation/Drivers/Classic/SoilParam.md`, which reverses the last two option-gated columns and omits one block. **A matching count is not a pass**: the reader walks the line with `strtok` and stops, dropping surplus columns silently — the shipped sample has 54 and consumes 53, `JULY_TAVG_SUPPLIED` being `FALSE` (`cl/read_soilparam.c:49-57,576`). Check the snow-band line for `1 + 3 x SNOW_BAND` tokens and each forcing file name against `<prefix><lat>_<lon>` at `GRID_DECIMAL` places, columns in `FORCE_TYPE` order. **Steps, image**: confirm the domain mask and `run_cell` are integer-typed with no `run_cell == 1` outside the mask, that parameter and domain files agree on grid dimensions and coordinates to 0.01, and that the forcing time axis is regular, starts 1 January 00:00, carries the global file's calendar and gives a step equal to `SNOW_STEPS_PER_DAY`. **Known-good reference**: the VIC sample data (Stehekin) ships a complete input set for both drivers, but its global files do not run as shipped: every path is written `${VIC_SAMPLE_DATA}/…`, neither parser expands a shell variable (`cl/get_global_param.c:409-411`), and the paths omit the `parameters/` subdirectory. **Cost**: one line, one cell, one header per check. **Invalidated by**: image validating almost none of the soil values classic rejects, so a NetCDF set passing these checks can still be impossible.

## 6. Area-weighted basin aggregation

**Inputs**: per-cell outputs plus a cell area for each. **Minimal check**: establish where the area comes from — **VIC writes none to output.** Classic computes one only from `RESOLUTION` and `EQUAL_AREA`, used only under `LAKES` (`cl/compute_cell_area.c:27-48`); image reads the domain area, again only under `LAKES`, and the domain fraction variable is read but **never used numerically** (`shim/get_global_domain.c:108-120`). **Steps, classic**: parse the coordinates out of each file name — the soil-file values at `GRID_DECIMAL` places — compute the area yourself and weight by it. **Steps, image**: take the area and, on a fractional grid, the fraction from the domain file and weight the unfilled cells of each slice. **Cost**: one domain file, or one pass over file names. **Invalidated by**: treating VIC's grid-cell values as already area-weighted — each is a mean over that cell's tiles and bands only (`sh/put_data.c:593`); including filled cells; a fraction that is not 1 everywhere.

## 7. Handing runoff and baseflow to a router

**Inputs**: `OUT_RUNOFF`, `OUT_BASEFLOW`, the model step and the aggregation frequency. **Minimal check**: both are `SUM`, in **mm of depth over the grid cell accumulated over the window** — not a rate, not a volume, not divided by any area. **Steps**: state what VIC guarantees and no more. The value is a depth over the whole grid cell, combined over tiles and bands; total local runoff is their sum, with no lag, channel storage or cell-to-cell transfer; the time coordinate is the **beginning** of the window, whose extent is `time_bnds` in image; and no cell area is in the output, so a conversion must supply one — a rate is depth over window length, a volume depth times area over 1000. **Cost**: one pass over both variables. **Invalidated by**: reading the stamp as the interval's end, which shifts the hydrograph by one window; using `OUT_INFLOW` (infiltration) in place of runoff; a run with lakes, where part of the runoff enters the lake tile and is reported again through `OUT_LAKE_*`; assuming the routing extension was compiled in.

## 8. Restart continuity check

**Inputs**: the state file, the two global files and the records either side of the boundary. **Minimal check**: **neither driver checks the state file's date or any physics option** (`cl/check_state_file.c:40-67`, `shim/vic_restore.c:910-1100`), so do it by hand. **Steps**: (1) read the date out of the state file name — the **end** of the step matching the four `STATE*` fields — and confirm the continuing run starts there; (2) diff the two global files and confirm `NLAYER`, `NODES`, `SNOW_BAND`, `LAKES`, `FROZEN_SOIL`, `FULL_ENERGY` and `BASEFLOW` match; (3) compare `OUT_SWE`, `OUT_SOIL_MOIST` and `OUT_WDEW` across the boundary, which should agree to output precision as `END` states of adjacent windows. **Cost**: two records, two text files. **Invalidated by**: a state date that is not a step boundary — the trigger is exact four-field equality and a mismatch writes **no file and no warning**; comparing an `AVG` flux instead of an `END` state; an image restart onto a different active-cell pattern.

## 9. When no full re-read is needed

- No data read: which variables exist with their units and aggregation (one header, or the lookup); whether the configuration matches this pack (the global file plus one output header, [version.md](version.md)); where a variable comes from ([processes.md](processes.md), not a sensitivity run).
- Two records: a period change in a storage state, or whether two runs differ at all. A full pass **is** needed for a period total or mean of a `SUM` or `AVG` variable, extremes, event detection and every closure recipe above.
