# VIC — card

Pinned to VIC `14a371a8` (tag `5.1.0`), sample data `3f2dcb4` ([version.md](version.md)); `path:line` is relative to that root. Any name: `tools/hcm_lookup.py --pack vic <NAME>`, from `catalogs/*.yaml` extracted from this commit — **not exhaustive**; read each `note`. Shorthand: **run** = `vic/vic_run/src`, **sh** = `vic/drivers/shared_all/src`, **cl** = `vic/drivers/classic/src`, **im** = `vic/drivers/image/src`, **shim** = `vic/drivers/shared_image/src`, `vic_def.h` = `vic/vic_run/include/vic_def.h`.

**What a cell is.** One independent column per cell; nothing is exchanged between cells. A cell holds its veg parameter file's tiles plus **one bare-soil tile appended last**, with the remaining fraction and a class one past the library (`cl/read_vegparam.c:441-447`), each repeated over `SNOW_BAND` bands (`run/vic_run.c:122,209`); soil is `NLAYER` moisture layers (max 3) and, outside `QUICK_FLUX`, `NODES` thermal nodes (max 50, `vic_def.h:42-43`). **External in 5.1.0**: channel routing — none in classic, in image only a build-time extension whose default is empty functions (`vic/drivers/image/Makefile:29`) — and forcing disaggregation, which VIC 5 does not do.

**Two drivers.** *Classic* (`vic_classic`, serial + OpenMP): ASCII or binary, **one forcing file and one output file per cell**, named from the cell's coordinates at `GRID_DECIMAL` places (`cl/make_in_and_outfiles.c:27-83`); soil, veg, veg library and snow bands are four ASCII tables, and `FORCE_TYPE` lines are **positional**. *Image* (`vic_image`, MPI + OpenMP): a NetCDF domain file, a NetCDF parameter file and forcing by calendar year, `<prefix><YYYY>.nc` (`im/vic_force.c:67-68`); `FORCE_TYPE` maps a VIC name to a NetCDF variable, and the forcing step comes **from the file's own time axis**, then must equal `SNOW_STEPS_PER_DAY`, the calendar likewise (`:556-577`). Both expect air temperature **C**, precipitation **mm per forcing step**, pressure and vapour pressure **kPa** (x1000 on read), radiation W/m2, wind m/s (`cl/vic_force.c:107-118`, `im/vic_force.c:393-399`).

**Time steps** (`cl/get_global_param.c:692-864`; image `:550-700` of its own parser). Each of `MODEL_STEPS_PER_DAY`, `SNOW_STEPS_PER_DAY`, `RUNOFF_STEPS_PER_DAY` and `ATMOS_STEPS_PER_DAY` (classic only) must lie in 4..1440 — only the model step may be 1 — and **any value above 24 must be an exact multiple of 24** — the fatal test `x % 24 != 0`, so 48 is legal, 36 is not (`:715-720,753-758,785-790,824-829`). The snow step must equal the model step unless that is daily (`:731-736`); runoff and atmos steps must be multiples of the model step, and atmos **also** of the snow step, defaulting to 24 when absent (`:800-851`). `NF = snow/model steps`; `NR = 0` when `NF == 1` (`:858-864`).

**A record's time stamp is the BEGINNING of its aggregation window** — `time_bounds[0]`, both drivers (`shim/vic_write.c:197-205`, `cl/write_data.c:41-44,133-141`); `time_bnds` carries both ends — the opposite convention from many land models.

**What a value means.** Per model step `sh/put_data.c` writes water fluxes as a **depth in mm over the step**, not a rate, and energy fluxes in W/m2; `sh/agg_data.c:44-83` then applies the aggregation type over the window — `SUM`, `AVG` (sum / step count), `MAX`, `MIN`, `END` (last step), `BEG` (first) — and image writes it as `cell_methods`. Defaults: `sh/vic_history.c:214-303`. A summed depth over a day is a daily total; a summed W/m2 is not a flux; an `END` state is one instant. A `units` string is metadata, not arithmetic: where they disagree the filling code wins.

**Missing values.** Image history carries a `_FillValue` per variable (`shim/vic_init_output.c:451-484`), applied to every cell outside the active list at gather time (`shim/vic_mpi_support.c:1691-1778`). Classic ASCII and binary have **no fill convention**: every row is data, and `-99999` (`MISSING`, `vic_def.h:34`) is a value the code declined to compute.
